Cibles URL enregistrées

Pour chaque cible, le bot suit toujours le même cycle : ouvrir l’URL, cliquer sur le lien indiqué (ou le lien principal si aucun libellé n’est saisi), attendre la redirection, puis recommencer selon le mode choisi — intervalle ou objectif. Aucun workflow à construire.

Réglages communs

Ces boutons appliquent la valeur à toutes les fiches enregistrées. Ni le nombre cible ni la durée n’ont de plafond arbitraire (durée : 1 à 365 jours).

Ajouter une cible

Facultatif. Renseigné, le bot clique le lien ou le bouton visible dont le libellé correspond exactement (casse, accents et espaces normalisés). Vide, il se contente de cliquer : s’il n’y a qu’un élément cliquable, c’est celui-là; sinon l’élément principal (le plus grand, avec du texte, hors navigation) est utilisé.

Mode d’exécution

Le moteur OCR (Tesseract.js/WASM) est inclus dans l’extension et démarre au premier cycle.

La confirmation est activée par défaut. Décoche-la pour laisser les cycles du mode intervalle s’enchaîner sans pause; les libellés sensibles restent toujours soumis à confirmation.

Proxys (Webshare, Rayobyte…)

Chargement…

Aucun proxy enregistré. Colle ta liste Webshare ou Rayobyte dans « Import en masse » ci-dessous.

Ajouter un proxy

Formats acceptés : host:port:user:pass, user:pass@host:port ou host:port avec les identifiants communs. Le proxy activé est appliqué juste avant le clic, puis le réglage Chrome précédent est restauré après la redirection; Chrome l’applique à tout le profil pendant cette fenêtre. Les identifiants restent dans chrome.storage.local sur cet appareil, ne partent jamais vers un serveur et ne sont pas écrits dans les logs.
